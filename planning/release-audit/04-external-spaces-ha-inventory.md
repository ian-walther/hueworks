# Chunk 4: External Spaces, Mappings, HA Inventory

Status: complete; implementation reconciled 2026-07-26. Scope: `external_spaces.ex`, `space_mappings.ex`, `space_suggestions.ex`, `inventory.ex`, `area_design.ex`, import-plane call sites. No open findings — ES-1 (the audit's only high-severity finding) and ES-2 are implemented and verified.

## Durable Boundary Rule (established by ES-1, keep enforcing)

**Never `Map.put_new` atom keys onto import-plane maps.** Import-plane data crosses JSON boundaries and arrives string-keyed; `Normalize.fetch/2` prefers atom keys, so injecting atom defaults *shadows* real string-keyed values. This inverted-precedence bug produced the only high-severity finding of the release audit (floors persisted under the bridge-default kind → reviewed floor mappings crashed `apply_explicit_space_mappings` mid-transaction, spaces double-filed across sync paths, parent links severed, saved mappings never prefilled). The rule sits alongside the earlier "only `StateParser` accepts loose payloads" boundary rule. `Hueworks.Import.SpaceIdentity` is the enforcement point for space identity: fetch-first, default-last, explicit attrs maps. The rule struck a second time during RC-1's fixture rollout: `ReimportPlan.build/3`'s `Map.put(:lights, ...)` on dual-shape input could resurrect filtered exported wrappers (see `08-`); its fix establishes the complementary pattern — when a function *writes* to an import-plane map, canonicalize the whole map to string keys at the boundary (`NormalizeJson.to_map/1`) first.

## Explicitly Fine / Leave-Alone

- **`SpaceIdentity` extraction** (the ES-1 fix, verified line-by-line): `identity/2` and `attrs/2` derive kind/external_id via dual-key `Normalize.fetch` with bridge defaults only as fallback; `SpaceMappings` and `SpaceSuggestions` both consume it; the diverged `default_kind/1` copies are unified (`:ha` clause included); `ensure_identity`'s `Map.put_new` pattern is deleted. Guardrails are exactly as decided: JSON-round-tripped (`blob_shaped/1`) fixtures drive a full floor-mapping `Materialize.materialize` and a cross-path consistency test proving `AreaDesign.refresh` and `SpaceMappings.sync_and_apply` persist identical identities.
- **Batch-scoped parent resolution** (the ES-2 fix, verified): when a reported parent is absent from the current sync batch, `ExternalSpaces` now falls back to the persisted parent row (`existing_parent_id/3`) instead of severing the link; parent still clears when the source genuinely reports none.
- **`ExternalSpaces` contract** (sync refreshes facts, never deletes unseen spaces, never touches mappings; `last_seen_at` + `stale?/2` diagnostics): matches the refinement doc's ExternalSpaceMappings rule. Upsert-in-transaction is race-safe for this single-writer SQLite deployment.
- **Placement precedence** in `SpaceMappings.target_id_for/4` — explicit reviewer choice (including explicit "unassigned") > import-plan destination > persisted mapping default — and its restriction to entity *insert* paths: existing placement stays authored HueWorks intent. `AreaDesign` respects the same boundary.
- **`Inventory`** read-only projection with native-source detection: sound separation. The `platform == "mqtt"` → `:z2m` heuristic can over-claim non-Z2M MQTT lights; acceptable for hedged guidance copy.
- **`SpaceSuggestions`** evidence model (member-match statuses, `:conflict` on disagreeing evidence, preselect only on `:confident`, ambiguity propagation): conservative and matches the "conflicting evidence" matrix requirement.
- **Suggestion/plan key encoding** (`Jason.encode!` + url-safe Base64 of `[kind, external_id]`): stable, collision-free, opaque to the DOM.
